# Код-ревью `ReviewMe.vue`

## 1. Разделение ответственности

Отображение продуктов стоит вынести в отдельный компонент. Тогда текущий компонент будет содержать только фильтры, а общий компонент будет отвечать за отображение, получение и обновление данных (туда же состояния loading и error).

## 2. Мутация props

В компоненте изменяются props, так делать нельзя: поток данных должен идти сверху вниз, а дочерние компоненты не должны менять state родителя.

Если фильтр должен быть объектом (хотя здесь одно поле, поэтому можно передать и строковый prop), по событию `input` нужно делать `emit`. Родитель сам обновит данные: нет локального state — нет проблемы.

## 3. Работа с вводом

`updateQuery` не стоит использовать напрямую в `input`. Лучше добавить в компонент `defineModel` и использовать на input `v-model`.

Значение можно хранить в локальном `ref` и следить за его обновлением через debounce. Debounce будет менять `modelValue`, который, в свою очередь, синхронизируется с родителем.

## 4. Логика обновления данных

`updateQuery` и `watch` вынести в родительский компонент. Плюс там есть race condition. Можно исправить сохранением id таймера во внешней переменной и при повторном изменении проверять: если он есть, значит отменяем через clearTimeout (а при успешном выполнении обнулять его).

## 5. v-for
Не хватает key (по идее линтер всегда это подсветит) и мутируем исходный массив. Тут нужен computed с toSorted методом.
